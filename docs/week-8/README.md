# Практическое занятие:«Создание MVP (продолжение). Проработка прототипа, пользовательских сценариев и критериев готовности MVP»

## Шаг 1. Уточнение цели MVP и метрики успеха

**Сегмент:** Гости вечеринок и домашних встреч — люди 18–45 лет, участники компаний от 5 до 20 человек.

**Ценность:** Возможность добавить свой трек в общую очередь и повлиять на музыку на вечеринке без установки приложений, регистрации и неловких просьб.

**Целевое действие на MVP:** Добавление трека в очередь гостем.

**Метрики проверки:**
 Доля гостей, добавивших хотя бы один трек (цель: не менее 40%)
 Доля гостей, сканировавших QR-код (цель: не менее 70%)

На MVP мы проверяем, что гости вечеринок готовы сканировать QR-код и добавлять треки в общую очередь, потому что получают возможность влиять на музыку без неловких просьб. Успех: 70% сканировавших QR-код, 40% добавивших хотя бы один трек.

## Шаг 2. Основной user flow

| Шаг | Действие |
|:---|:---|
| 1 | Компания собралась на вечеринке, нужно включить музыку. |
| 2 | Хост открывает сайт, нажимает кнопку «Создать комнату». |
| 3 | Система создаёт комнату и генерирует QR-код и ссылку. |
| 4 | Хост показывает QR-код на экране телефона. |
| 5 | Гость наводит камеру на QR-код, открывается страница комнаты. |
| 6 | Гость вводит название трека в поле поиска. |
| 7 | Гость ставит лайки понравившимся трекам в очереди. |
| 8 | Хост запускает воспроизведение. Треки с наибольшим количеством лайков поднимаются вверх. |
| 9 | Гость видит, что его трек добавлен в очередь и отображается на экране. |

## Шаг 3. Альтернативный сценарий

| Шаг | Действие |
|:---|:---|
| 1 | Гость вводит название трека в поле поиска. |
| 2 | Система возвращает пустой результат (трек не найден). |
| 3 | Система показывает сообщение: «Трек не найден. Попробуйте другой вариант написания или другой трек». |
| 4 | Гость видит сообщение и понимает, что пошло не так. |
| 5 | Гость исправляет запрос (другое написание, другой трек) и повторяет поиск. |
| 6 | Трек найден, гость добавляет его в очередь. |
| 7 | Гость видит подтверждение: «Трек добавлен в очередь». |

## Шаг 5. Модель данных / сущностей

| Сущность | Поля | Связи |
|:---|:---|:---|
| **Комната** | ID комнаты, дата создания, статус (активна/завершена), ID хоста | Имеет очередь треков |
| **Трек** | ID трека, название, исполнитель, | Принадлежит комнате, имеет список голосов |
| **Голос (лайк)** | ID голоса, ID трека, | Привязан к треку |
| **Гость** | ID сессии, никнейм | Может добавлять треки и голосовать |

## Шаг 6. Backlog ядра MVP: user stories + acceptance criteria

| ID | User Story | Acceptance Criteria | Priority | Зависимости/Риски |
|:---|:---|:---|:---|:---|
| US-01 | Как хост, я хочу создать комнату без регистрации в один клик, чтобы начать вечеринку быстро. | 1. Кнопка «Создать комнату» доступна без авторизации.<br>2. Комната создаётся. <br>3. Хост не вводит никаких данных. | Must | Генерация уникальных ID |
| US-02 | Как хост, я хочу видеть QR-код и ссылку на комнату, чтобы поделиться с гостями. | 1. QR-код отображается сразу после создания.<br>2. Ссылка отображается под QR-кодом.<br>3. Есть кнопка «Копировать ссылку». | Must | Библиотека QR-кодов |
| US-03 | Как гость, я хочу подключиться к комнате по QR-коду, чтобы участвовать без установки приложений. | 1. При сканировании открывается страница комнаты.<br>2. Загрузка.<br>3. Гость не вводит логин и пароль. | Must | Стабильность QR-кода |
| US-04 | Как гость, я хочу добавить трек в очередь, чтобы он сыграл на вечеринке. | 1. У каждого результата есть кнопка «Добавить».<br>2. После добавления трек появляется в очереди.<br>3. Гость видит трек | Must | Большой размер данных |
| US-05 | Как гость, я хочу ставить лайки трекам в очереди, чтобы влиять на порядок воспроизведения. | 1. У каждого трека в очереди есть кнопка лайка.<br>2. Количество лайков отображается.<br>3. Один гость — один лайк на трек. | Must | Нет |
| US-06 | Как гость, я хочу видеть, как очередь меняется в реальном времени, чтобы понимать влияние моих лайков. | 1. Очередь обновляется без перезагрузки.<br>2. Треки сортируются по количеству лайков.<br>3. При равных лайках — порядок добавления. | Must | WebSockets |
| US-07 | Как хост, я хочу запустить воспроизведение треков из очереди, чтобы музыка играла через колонку. | 1. Кнопка «Play».<br>2. Воспроизведение через браузер хоста.<br>3. Треки играют последовательно. | Must | Web Audio API |
| US-08 | Как гость, я хочу видеть текущий трек и очередь, чтобы знать, когда сыграет мой трек. | 1. Отображается текущий трек.<br>2. Отображается полная очередь. <br>3. Интерфейс обновляется в реальном времени. | Must | WebSockets |

## Шаг 7. Definition of Done для MVP

| № | Критерий |
|:---|:---|
| 1 | Реализованы все Must-истории |
| 2 | Основной user flow проходит без ошибок |
| 3 | Альтернативный сценарий «трек не найден» обработан и показывает понятное сообщение |
| 4 | MVP работает на  мобильных устройств |
| 5 | Все критические и блокирующие дефекты исправлены |
| 6 | Подготовлен сценарий демо  |
| 7 | Оформлена инструкция для хостов  |
| 8 | Зафиксированы ограничения MVP |
| 9 | MVP доступен по публичной ссылке |
| 10 | Данные разных комнат изолированы|
