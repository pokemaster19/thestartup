# Актуализация ценностного предложения 
Для компании друзей на вечеринке в ситуации, когда разность музыкальных вкусов 
начинает портить атмосферу и вызывать споры, наше решение обеспечивает демократичный механизм выбора музыки,
где каждый гость может добавить свой трек и повлиять на очередь голосованием, улучшая дружелюбность
атмосферы и снижая количество конфликтов по сравнению с хаотичной
передачей телефона по кругу, при условиях, что гости не устанавливают
приложения, не регистрируются и хост создает комнату без регистрации.
## Тезисы 

Нулевой порог входа — Гости попадают в комнату по QR-коду без установки приложений и регистрации.

Прозрачность механики — Гость сразу видит, как лайки влияют на очередь: трек с большим количеством голосов
поднимается вверх. Видимый результат создает доверие к механизму.

# Декомпозиция ценности в пользовательский сценарий 

## Основной пользовательский сценарий

1. **Триггер** — Компания собралась на вечеринке, нужно включить музыку.

2. **Вход хоста** — Хост открывает сайт, нажимает кнопку «Создать комнату».

3. **Создание комнаты** — Система создаёт уникальную комнату и мгновенно генерирует QR-код.

4. **Приглашение гостей** — Хост показывает QR-код на экране своего телефона.

5. **Вход гостя** — Гость наводит камеру телефона на QR-код (или переходит по ссылке). Открывается веб-страница комнаты без установки приложений и регистрации.

6. **Ключевое действие: добавление трека** — Гость видит поле поиска, вводит название трека или исполнителя, выбирает из результатов и нажимает «Добавить в очередь».

7. **Ключевое действие: голосование** — Гости ставят лайки трекам в очереди. Система автоматически пересортировывает очередь: треки с большим количеством лайков поднимаются выше.

8. **Получение результата** — Хост запускает воспроизведение. Треки играют в порядке очереди через колонку, подключённую к устройству хоста.

9. **Фиксация результата** — Гости видят, как их лайки влияют на очередь в реальном времени. Трек с лайками поднимается наверх и играет раньше.

10. **Завершение** — Вечеринка заканчивается.

## Альтернативный сценарий: Ошибка — трек не найден

1. **Триггер** — Гость вводит название трека в поиск.

2. **Ошибка** — Система возвращает пустой результат.

3. **Сообщение** — Система показывает понятное сообщение: "Трек не найден.".

4. **Действие пользователя** — Гость исправляет запрос (другое написание, другой трек) или переходит к добавлению другого трека.

5. **Успех** — Гость успешно добавляет другой трек в очередь.

6. **Результат** — Пользователь не блокируется и продолжает использовать сервис.


## Альтернативный сценарий: Коллективный пропуск трека

1. **Триггер** — Играет трек, который не нравится большинству гостей.

2. **Действие** — Несколько гостей нажимают кнопку «Пропустить» рядом с текущим треком.

3. **Проверка порога** — Система считает количество голосов за пропуск.

4. **Пропуск** — Когда количество голосов достигает 60% от активных участников, трек пропускается.

5. **Результат** — Система автоматически запускает следующий трек в очереди. Конфликта не возникает, потому что решение коллективное.


## Карта функций: Core (ядро MVP)

| Функция | Шаг сценария | Какой элемент ценности обеспечивает |
|:---|:---|:---|
| Создание комнаты без регистрации | Вход хоста | Хост запускает сервис и не тратит время на регистрацию и подтверждение почты. |
| Генерация QR-кода и ссылки для входа | Создание комнаты | Гости подключаются мгновенно — навели камеру и попали в комнату. Не нужно устанавливать приложения, регистрироваться или искать комнату по названию. |
| Поиск и добавление треков в очередь (интеграция с Яндекс.Музыкой / VK) | Ключевое действие: добавление трека | Гость находит любимую музыку в привычном каталоге и добавляет её в общую очередь. |
| Голосование за треки (лайки) | Ключевое действие: голосование | Гость может выразить своё мнение и повлиять на очередь. Лайк — это механизм демократии, который заменяет крики «поставь это» и споры. |
| Автоматическое упорядочивание очереди по количеству голосов | Ключевое действие: голосование | Прозрачность: треки с большим количеством лайков поднимаются вверх, и гости видят, что их голос важен. Без этого голосование теряет смысл. |
| Воспроизведение треков на устройстве хоста | Получение результата | Музыка физически играет через колонку, подключенную к телефону хоста. |
| Отображение текущего трека и очереди | Получение результата и фиксация результата | Прозрачность для гостей: видно, что сейчас играет и что будет дальше. Снижает тревожность «когда же мой трек». |

## Карта функций: Support

| Функция | Шаг сценария | Назначение |
|:---|:---|:---|
| Аватарки или никнеймы гостей (опционально, без регистрации) | Вход гостя | Социальный аспект — видно, кто добавил трек. Повышает вовлеченность и создаёт ощущение сообщества. |
| Коллективное голосование за пропуск (скип) текущего трека | Получение результата | Защита от трека, который не нравится большинству. Скип происходит только при достижении порога голосов, что предотвращает диктатуру одного человека. |
| Сохранение понравившегося трека в личный плейлист | Фиксация результата | Ценность для гостя: он не теряет музыку, которая ему понравилась, даже если не знает названия. Увеличивает лояльность и возврат в сервис. |
| Базовый плейлист «по умолчанию» при создании комнаты | Создание комнаты | Решает проблему «холодного старта» — комната не пустует, пока гости добавляют треки. Музыка играет с первой секунды. |
| Адаптивный дизайн под мобильные устройства | Вход гостя и ключевое действие: добавление трека | Интерфейс удобен на телефонах гостей. Без этого снижается скорость и простота добавления треков. |
| Автоматическое обновление очереди в реальном времени | Ключевое действие: голосование и фиксация результата | Гости видят изменения без перезагрузки страницы. Повышает доверие к механизму голосования. |

## Карта функций: Later

| Функция | Причина отложить |
|:---|:---|
| История комнат и статистика | Не влияет на базовую ценность — голосование и очередь. Можно добавить на втором этапе для удержания и премиума. |
| Эквалайзер и настройки звука | Улучшает качество, но не является критическим для MVP. Готовый плейлист и голосование важнее. |
| Чат внутри комнаты | Социальная функция, но на вечеринке люди общаются вживую. Чат может отвлечь от реального общения. |
| Нативные мобильные приложения (iOS/Android) | Начать с PWA/веб-версии достаточно для проверки гипотез. Нативные приложения требуют больше ресурсов и времени разработки. |
| Подборки по жанрам и настроению | Дополнительная ценность, но не критична для MVP. Можно добавить позже для удержания. |
| Интеграция с Spotify (международная) | Приоритет — российские стриминги (Яндекс, VK). Spotify можно добавить на втором этапе при выходе на международный рынок. |
| Рекламные интеграции и партнерские программы | Функция монетизации, не влияет на базовую ценность. Запускается после накопления аудитории. |
| B2B-инструменты модерации (стоп-листы, белый список) | Необходимы для баров, но для MVP с фокусом на B2C (домашние вечеринки) не критичны. |
